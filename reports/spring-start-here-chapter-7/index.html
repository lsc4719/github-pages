01

먼저 웹 앱의 경계를 본다

브라우저는 요청을 보내고, 백엔드는 로직과 데이터를 처리한 뒤 응답한다. 한 백엔드가 여러 사용자의 요청을 동시에 처리한다는 점이 중요하다.

Frontend

사용자와 직접 만나는 쪽

브라우저가 HTTP 요청을 보내고 응답을 해석한다. 서버가 완성된 HTML을 줄 수도 있고, 별도 프런트엔드 앱이 JSON 같은 원시 데이터를 받아 화면을 만들 수도 있다.

Backend

행동과 데이터를 책임지는 쪽

요청에 맞는 비즈니스 로직을 실행하고 필요하면 데이터를 저장한다. 여러 클라이언트가 동시에 접근하므로 공유 자원과 동시성을 의식해야 한다.

Server-rendered

서버가 화면을 완성

백엔드가 HTML, CSS, JavaScript 등 브라우저가 바로 표시할 결과를 만든다. 작은 앱에서 단순하고 생산적인 선택이 될 수 있다.

Separated

프런트엔드와 백엔드를 분리

백엔드는 주로 JSON/XML 데이터를 제공하고 독립 프런트엔드가 화면을 구성한다. 팀과 배포를 분리하기 쉬워 큰 시스템에 유리하다.

Servlet container의 역할

Tomcat 같은 서블릿 컨테이너는 네트워크의 HTTP 요청/응답을 Java 객체와 메서드 호출로 번역한다. 애플리케이션은 저수준 통신 구현 대신 업무 로직에 집중한다.

02

Spring Boot의 “마법”은 합리적인 기본값이다

숨겨진 마법이 아니라 반복 설정을 줄이는 세 가지 장치의 조합이다.

1 · Initializr

프로젝트 뼈대 생성

start.spring.io가 빌드 도구, Java/Spring Boot 버전, 패키지 정보와 의존성을 반영한 실행 가능한 시작점을 만든다.

2 · Starters

기능 단위 의존성

spring-boot-starter-web처럼 “필요한 능력”을 선언하면 관련 라이브러리와 호환 버전 묶음을 가져온다.

3 · Auto-configuration

관례 기반 설정

클래스패스의 의존성을 보고 일반적인 구성을 제공한다. 웹 starter가 있으면 내장 Tomcat과 MVC 구성 요소를 준비하는 식이다.

핵심 사고법

“기본 설정을 전부 작성”하는 대신 “관례에서 벗어나는 부분만 재정의”한다. Boot는 복잡성을 없애기보다 검증된 기본값 뒤로 이동시킨다.

03

Spring MVC 요청의 7단계

개발자가 주로 작성하는 것은 Controller다. 나머지 흐름은 Spring Boot가 구성한 MVC 구성 요소들이 협업한다.

1

Browser

경로와 HTTP 메서드를 담아 요청한다.

2

Tomcat

HTTP를 받아 애플리케이션의 서블릿으로 전달한다.

3

Dispatcher

모든 요청의 진입점인 Front Controller가 흐름을 조정한다.

4

Mapping

Handler Mapping이 경로와 메서드에 맞는 action을 찾는다.

5

Controller

선택된 메서드가 실행되고 view 이름과 데이터를 돌려준다.

6

Resolver

View Resolver가 이름에 해당하는 화면을 찾아 렌더링한다.

7

Response

Tomcat을 통해 응답이 돌아가고 브라우저가 표시한다.

실패 지점: Handler Mapping이 대응 action을 찾지 못하면 404 Not Found가 된다. 즉 URL 경로뿐 아니라 HTTP 메서드 매핑도 요청 라우팅의 일부다.

04

최소 웹 페이지 구현

정적 HTML 하나와 요청을 연결하는 Controller action 하나면 전체 흐름을 관찰할 수 있다.

Dependency

웹 기능 선언

<dependency>
  <groupId>org.springframework.boot</groupId>
  <artifactId>spring-boot-starter-web</artifactId>
</dependency>
Controller

요청과 화면 연결

@Controller
class MainController {
  @RequestMapping("/home")
  String home() {
    return "home.html";
  }
}
  • resources/static/home.html에 표시할 정적 페이지를 둔다.
  • @Controller로 클래스를 Spring 관리 대상으로 만든다.
  • @RequestMapping("/home")으로 요청 경로를 action에 연결한다.
  • 앱을 실행하고 http://localhost:8080/home에서 확인한다.
05

빠른 복습

질문을 먼저 답해 본 뒤 펼쳐서 확인한다.

Starter와 자동 구성은 무엇이 다른가?

Starter는 기능에 필요한 호환 의존성 묶음이고, 자동 구성은 그 의존성이 존재한다는 사실을 바탕으로 일반적인 객체와 설정을 준비하는 메커니즘이다.

Tomcat과 DispatcherServlet의 책임은 어떻게 나뉘나?

Tomcat은 HTTP와 Java 애플리케이션 사이의 통신 경계를 담당하고, DispatcherServlet은 Spring MVC 내부에서 적절한 controller와 view로 요청을 배분한다.

개발자가 직접 구현해야 하는 핵심 구성 요소는?

이 장의 최소 예제에서는 HTML view와 Controller action이다. Handler Mapping, View Resolver, DispatcherServlet 등은 Spring Boot가 구성한다.
