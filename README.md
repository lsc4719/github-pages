# Reports on GitHub Pages

[보고서 목록](https://lsc4719.github.io/github-pages/) · 공개 저장소이므로 비공개 정보는 넣지 않습니다.

## 작성 원칙

**독자가 무엇을 이해하고, 판단하고, 바꿔야 하는지**를 중심으로 씁니다.

- 제목과 첫 1~3문장에 핵심 판단과 첫 행동을 제시합니다. 요청의 목적에 맞는 포인트 몇 개를 골라 깊이 설명합니다.
- 각 포인트는 **구체적인 사례 → 놓친 점·원인 → 개선안 → 다음에 적용할 행동**으로 연결합니다. 개념 설명이라면 사례·도식으로 원리와 차이를 보여 줍니다.
- 통계·이력·배경은 판단에 필요한 만큼만 씁니다. 개선 방법을 요청받았다면 현황 요약보다 **무엇을 어떻게 고칠지**에 본문을 할애합니다.
- 같은 내용을 요약·카드·차트·결론에서 반복하지 않습니다. 상투적인 조언, 긴 서론, 장식용 섹션, 제작 과정과 UI 설명은 덜어냅니다.
- 근거·조건·예외는 해석에 필요한 위치에 짧게 남깁니다. 사실과 추론을 구분하고, 일부 사례를 전체의 경향이나 원인으로 단정하지 않습니다.
- 출처는 하단에 의미 있는 자료명으로 모읍니다. 본문에서 필요하면 용어·사례에 직접 링크하고, 숫자 인용 표식이나 URL 나열은 피합니다.

## 사례와 시각화

**시각화가 이해를 돕는 주제는 그림·실제 장면을 본문의 중심에 둡니다.** 설명은 무엇을 봐야 하는지와 그 의미를 짚습니다.

- 체스: 실제 대국의 결정 장면을 골라 **놓친 위협 → 실전 수의 결과 → 개선 수**를 체스판과 화살표로 비교합니다. 기보·배치·수순의 합법성을 검증하고, 개선 수는 가능한 경우 엔진으로 재검토합니다. 실전과 가상 수순을 구분합니다.
- 개념·구조: 흐름·의존·분기를 도식으로, 정확한 대응·비교는 표로 보여 줍니다. 실제 수치·추세가 필요할 때만 차트를 사용합니다.
- 인터랙션은 수순 진행·대안 비교처럼 이해에 도움이 될 때 추가합니다. 조작부·결과·설명은 가까이 두고, 선택 상태와 키보드 조작을 제공합니다. 떨어진 카드의 강조만 바꾸는 조작은 만들지 않습니다.
- 핵심 설명과 실행 지침은 기본 노출합니다. 단순한 내용을 읽기 위해 탭·필터를 누르게 하지 않으며, 인쇄 시에도 핵심 사례와 개선안이 남게 합니다.

참조: [다음 대국에서 고칠 세 가지](reports/chess-rating-1200-review/). 다른 주제에도 **선명한 포인트와 구체적인 사례**라는 편집 방식을 적용하되, 섹션 수나 형식을 기계적으로 복제하지 않습니다.

## 화면과 접근성

- 연한 베이지·아이보리 배경, 짙은 글자, 절제된 세이지·테라코타 포인트를 사용합니다. 시스템 다크 모드에서도 밝은 스타일과 대비를 유지합니다.
- 모바일 한 열을 기본 HTML/CSS로 완성하고, 넓은 화면만 `min-width`로 확장합니다. 본문은 `1.125rem`, 줄 높이 약 `1.7`, 좌우 여백 `1rem`을 출발점으로 삼습니다.
- 큰 표지·빈 박스·중첩 카드·고정 높이를 피합니다. 홈의 보고서 카드는 유지하되, 본문은 글자 위계와 구분선으로 정리합니다.
- 긴 비교표는 모바일에서 항목별 목록으로 바꿉니다. 숫자 표에만 영역 내 가로 스크롤을 허용하고, 페이지 전체 넘침이나 글자·도식의 무리한 축소를 피합니다.
- 목차는 짧은 앵커 링크를 사용하며 드롭다운·고정 목차를 만들지 않습니다. 링크·버튼은 44px 이상의 터치 영역을 목표로 합니다.
- viewport 메타 태그를 넣고 확대를 막지 않습니다. 이미지 대체 텍스트, 표 머리글, 초점 표시를 제공하고 색상만으로 의미를 전달하지 않습니다.

**게시 전:** 320·360·390·430px와 200% 확대에서 읽기 순서, 글자·체스판의 가독성, 조작부와 결과의 거리, 잘림·넘침을 확인합니다. 실제 확인한 범위와 미검증 항목은 작업 결과나 커밋에 기록합니다.

## 파일과 게시

| 파일 | 역할 |
| --- | --- |
| `reports/<slug>/index.html` | 개별 보고서. 전용 이미지·CSS·자료도 같은 디렉터리에 둡니다. |
| `index.html` | 홈의 보고서 카드와 링크 |
| `reports.json` | 보고서 메타데이터. 홈에 자동 반영되지 않습니다. |
| `.github/workflows/pages.yml` | `main` 변경 시 GitHub Pages 자동 배포 |

1. 영문 소문자·하이픈의 고유한 slug로 보고서를 작성합니다. 링크와 자산 경로는 `/github-pages/` 배포 경로에 맞는 상대 경로를 사용합니다.
2. 홈 카드와 `reports.json`을 함께 갱신합니다. 메타데이터는 `slug`, `title`, `summary`, `date`(`YYYY-MM-DD`), `path`(`./reports/<slug>/`)입니다.
3. 저장소 루트에서 `python3 -m http.server 8000`으로 열어 링크·자산·조작을 확인합니다.
4. 커밋 후 `main`에 반영하고 **Deploy GitHub Pages** 성공 및 공개 목록·보고서 URL을 확인합니다.

보고서 주소: `https://lsc4719.github.io/github-pages/reports/<slug>/`
